# 발표 진행 큐시트

**발표 중에는 [큰 글씨 통합 대본](presentation/스터디예약_통합발표대본.docx) 하나를 열어 두세요.** 화면 지시 → 그 화면에서 할 말 → 확인 질문 → 다음 장 연결이 슬라이드별로 이어집니다. 이 가이드는 준비와 시간 배분만 빠르게 확인하는 큐시트입니다.

[GitHub에서 바로 읽는 같은 대본](presentation/발표진행대본.md) · [PPT 48장](presentation/스터디예약_AWS확장판.pptx) · [슬라이드별 실제 파일 지도](slides-map.json)

## 발표 전에 준비

저장소 루트에서 순서대로 실행합니다. 첫 이미지·의존성 다운로드와 전체 검사는 발표 전에 끝냅니다.

```bash
./dev up
./dev verify
./dev status
```

브라우저 <http://localhost:3000>, PPT, IDE와 대본을 함께 열어 둡니다. 로컬 계정은 `demo-a` 또는 `demo-b`, 비밀번호는 `demo-pass-2026`입니다. `status`의 `passed`와 검증한 소스·현재 소스 해시 일치를 확인합니다. `stale`이거나 결과가 없으면 다시 검사합니다.

**완성본을 설명하는 수업입니다.** 인터뷰는 이미 합의한 정책의 재연으로 보여줍니다. 현장에서 앱을 다시 생성하거나 현재 통과하는 검사를 실패 중이라고 설명하지 않습니다.

현재 범위는 로컬 앱·로그인·검사와 AWS 코드의 정적 검사까지입니다. 실제 AWS 로그인·plan·apply·ECR push·운영 배포와 원격 GitHub Actions 실행은 하지 않았습니다. [AWS 상세](aws-login.md)는 설명용이며 현장에서 계정 작업을 실행하지 않습니다.

## 검사를 반복하지 않는 진행

- 4·42장: `./dev status`를 현장에서 확인합니다. 전체 검사를 다시 시작하지 않습니다.
- 21·22장: `skill-check`·`mcp-check`는 사전 결과를 설명합니다. 새 세션의 Skill·Hook·MCP 활성화는 별도 확인입니다.
- 27장: 4장에서 확인한 결과로 검사 범위를 설명하며 status를 다시 실행하지 않습니다.
- 28장: 사전 반례 결과를 보여줍니다. 시간이 있으면 `./dev defect-demo`만 단독 실행합니다. DB·컴파일 오류를 성공으로 세지 않습니다.
- 32장: `infra-check`는 backend 없는 init·fmt·validate입니다. 현장에서는 도식을 설명하고 실계정 plan·apply는 실행하지 않습니다.

19장에서는 문서의 구현용 요청을 그대로 실행하지 않습니다. 통합 대본에 넣은 읽기 전용 요청문을 읽는 것이 기본이며 AI 응답 대기는 선택입니다.

## 기본 종료와 AWS 심화 연결

42장에서 기본 설명을 끝낼 때: “여기까지가 로컬 검증을 끝낸 코드 투어입니다. 정책이 어디에 있고 어떤 검사가 그 약속을 확인하는지 연결할 수 있으면 됩니다.”

43장까지 이어갈 때: “앞에서는 AWS에서 어떻게 실행할지 코드로 봤습니다. 이제 실제 계정에서 실행하기 전에 필요한 로그인과 배포, 비용의 경계를 이어 보겠습니다.”

## 발표에 필요한 코드 깊이

모든 문법을 외울 필요는 없습니다. 정책·신원·잠금 순서·검사 근거·배포 권한을 자기 말로 설명하고 파일을 가리킬 수 있어야 합니다. 화면의 `register()`와 Spring의 `join()`은 서로 다른 함수입니다.

질문을 받으면 통합 대본의 `질문 답변과 보충 설명`으로 이동합니다. 96개 Q&A를 읽고 `발표로 돌아가기`를 누르면 같은 장으로 돌아옵니다. 파일 위치의 기준은 [slides-map.json](slides-map.json)이며 경로는 저장소 루트 기준입니다.
